# Agent 工程能力自检清单

**项目：** 命理大师  
**版本：** v1.0 (目标覆盖项) / v2.0 (后续补充)

---

## 1. Agent 基础 6 层

| # | 能力 | v1.0 | 项目中的实现 | 行业最佳实践对照 |
|---|------|------|-------------|-----------------|
| 1 | **推理循环 (agent-loop)** | ✅ | Go 内部 bounded state machine：收集资料 → 排盘 → 检索 → 回答 | ReAct / Plan-Execute / Supervisor 三种模式选其一，本项目 v1 先用确定性状态机 |
| 2 | **工具系统 (tool-system)** | ✅ | Eino Tool 接口：bazi_calc / knowledge_search / llm_generate | 工具注册中心 + JSON Schema 参数定义 + 超时/重试 |
| 3 | **上下文管理 (context-mgr)** | ✅ | 会话状态 + 当前问题 + 命盘结果 | 需要补充：压缩策略、滑动窗口、摘要回退 |
| 4 | **记忆系统 (memory)** | ⚠️ | Session 级：Go 内存状态 | 需要补充：持久化（SQLite/Redis）、跨会话记忆、长期用户偏好 |
| 5 | **安全边界 (safety)** | ✅ | Tool 白名单 + 八字参数范围校验 (年份 1900-2100) | 需要补充：内容审计日志、高风险操作审批 |
| 6 | **可观测性 (observe)** | ✅ | SSE thinking/tool_call/component 事件 + 结构化日志 | 需要补充：Token 用量统计、延迟监控、告警 |

## 2. Agent 决策 5 层

| # | 决策 | v1.0 | 项目选择 | 备选方案 |

## 3. 上下文工程 (Context Engineering)

> 行业共识：Agent 性能瓶颈已从提示工程转移到上下文工程。
> "上下文是 Agent 的一等公民。"

| # | 问题 | v1.0 | 解决方案 |
|---|------|------|---------|
| 7 | **上下文膨胀** | ✅ | LangGraph State 限制 messages 长度；Token 计数触发压缩 |
| 8 | **上下文中毒** | ⚠️ | 工具返回的错误信息可能污染上下文。v1.0 仅做工具结果校验 |
| 9 | **上下文干扰** | ✅ | 只把当前问题需要的命盘和引用送入回答阶段 |
| 10 | **上下文冲突** | ⚠️ | 用户可能先提供错误信息后修正。v1.0 通过资料变更触发重排处理 |
| 11 | **上下文压缩** | ✅ | 多轮对话超过阈值时，用摘要替代旧消息（"保框架、删冗余"） |
| 12 | **压缩质量** | ⚠️ | 摘要可能丢失关键细节（如精确时间）。v2.0 引入 LLM-as-Judge 评估压缩质量 |

## 4. 提示词工程 (Prompt Engineering)

> 行业共识：核心指令 ≤ 500 token。工具描述按模型理解能力重写，不照搬 API 文档。

| # | 问题 | v1.0 | 解决方案 |
|---|------|------|---------|
| 13 | **System Prompt 结构** | ✅ | 分区清晰：`[角色]` / `[任务]` / `[工具]` / `[输出格式]` |
| 14 | **Prompt 长度控制** | ✅ | 核心指令 ≤ 500 token；工具描述精简为模型理解版本 |
| 15 | **Prompt 模板管理** | ✅ | prompts/ 目录：extractor / planner / interpret / system 各自独立 |
| 16 | **Prompt 版本化** | ⚠️ | v2.0：Git 管理 Prompt 历史 + A/B 测试框架 |
| 17 | **动态 Prompt 组装** | ✅ | 按需注入：用户问题 + 排盘数据 + 知识引用 → 运行时拼装 |
| 18 | **Prompt Bloat 防护** | ✅ | 只注入当前步骤需要的信息；MCP 工具不预装全部 tool schema |

## 5. 工具可靠性 (Tool Reliability)

> 行业数据：一个 Tool 成功率 95% → 串联 5 个后复合成功率 ~77%。

| # | 问题 | v1.0 | 解决方案 |
|---|------|------|---------|
| 19 | **工具超时** | ✅ | 每个 Tool 有 context.WithTimeout (30s) |
| 20 | **工具失败降级** | ✅ | 失败返回结构化 error，Agent 可感知并重试或跳过 |
| 21 | **循环调用检测** | ✅ | 同一 Tool + 同一参数 ≥3 次 → 强制终止，推送错误给用户 |
| 22 | **级联失败** | ✅ | bazi_calc 失败 → 跳过 knowledge_search 和 generate → 告知用户 |
| 23 | **参数类型校验** | ✅ | Gin 层 JSON 校验 + Tool 层参数类型断言 |
| 24 | **并发工具安全** | ✅ | Go goroutine 隔离，每个 Tool 独立执行 |

## 6. 状态管理 (State Management)

> LLM 是"无状态函数"——每次调用都是重新开始。状态管理是 Agent 工程化的核心。

| # | 问题 | v1.0 | 解决方案 |
|---|------|------|---------|
| 25 | **多轮状态保持** | ✅ | Go SessionState: profile / bazi_result / last_user_question 跨轮次保持 |
| 26 | **状态持久化** | ⚠️ | v1.0: 内存存储，重启丢失。v2.0: SQLite Checkpoint |
| 27 | **会话恢复** | ⚠️ | 客户端传 sessionId，服务端内存查找。v2.0: SQLite 跨重启恢复 |
| 28 | **矛盾输入处理** | ✅ | 用户修正资料时清理旧命盘并重新排盘 |
| 29 | **状态隔离** | ✅ | 不同 sessionId 之间状态完全隔离 |
| 30 | **中断恢复** | ⚠️ | v2.0: LangGraph interrupt() + Command 实现人工审批中断 |

## 9. 技术实现清单

### 9.1 语言与框架

| 技术 | 用途 | 版本 |
|------|------|------|
| Go | 执行层核心语言 | 1.22+ |
| Python | v2 推理层语言 | 3.12+ |
| Gin | Go HTTP 框架 | latest |
| FastAPI | v2 LangGraph HTTP 框架 | latest |
| uvicorn | v2 LangGraph 服务运行 | latest |
| Eino | Go Tool/ChatModel/Session 抽象 | latest |
| LangGraph | Python 推理编排 (StateGraph) | latest |
| Vue 3 | 前端框架 | 3.x |
| Vite | 前端构建 | latest |
| Naive UI | UI 组件库 | latest |

### 9.2 外部服务

| 服务 | 用途 | 协议 |
|------|------|------|
| DeepSeek v4 API | LLM (问答) | HTTP/SSE |
| 项目知识库 MCP | 命理资料检索 | MCP |
| Gin Server (:8080) | Go 执行层 | HTTP + SSE |
| FastAPI Server (:8000) | v2 LangGraph 推理层 | HTTP |

### 9.3 关键算法

| 算法 | 实现 | 复杂度 |
|------|------|--------|
| 公历转农历 | 查表法 (1900-2100 节气数据) | O(1) |
| 四柱排盘 | 年上起月 + 日干支计算 + 五鼠遁 | O(1) |
| 十神计算 | 五行生克关系映射 | O(1) |
| 大运排盘 | 顺逆排 + 六十甲子轮转 | O(n) n=8 |
| 五行分析 | 遍历 + 计数 | O(1) |
